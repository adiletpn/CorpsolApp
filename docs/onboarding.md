# Заведение отдела одной командой

Когда людей больше двух-трёх, заводить их в панели по одному долго и
легко ошибиться в рабочем номере. Команда `onboard` делает то же самое
по файлу: создаёт отдел, заводит сотрудников в офис, привязывает логины
Kcell и номера Sipuni, назначает руководителя и добирает звонки.

## Файл со списком

Пример — [examples/roster.example.json](examples/roster.example.json).

| Поле | Что это |
|---|---|
| `department` | Название отдела. Если такой уже есть (регистр и пробелы не важны), люди добавятся в него. |
| `officeId` | Офис. Можно не указывать, если офис в организации один. |
| `resyncSince` | С какого дня добрать звонки после привязки, `ГГГГ-ММ-ДД`. Без поля — не добирать. |
| `employees[].name` | Имя, как оно будет видно в панели и приложении. |
| `employees[].role` | `MOP` (по умолчанию) или `ROP`. |
| `employees[].head` | `true` — руководитель отдела. Только один и только РОП. |
| `employees[].login` | Логин для входа. Без поля — из имени латиницей: «Карлыгаш» → `karlygash@corpsol.kz`. |
| `employees[].kcell` | Логин в АТС Kcell — часть адреса до `@`: `yarik@corpsol.vpbx.kcell.kz` → `yarik`. |
| `employees[].sipuni` | Внутренний номер в Sipuni. |

Файл проверяется целиком до первого запроса — все ошибки выводятся
разом. Только проверить, ничего не меняя:

```sh
npm run onboard -w @corpsol/api -- kvanta.json --check
```

## Запуск

```sh
CORPSOL_API_URL=https://corpsolapi-production.up.railway.app/api \
FIREBASE_WEB_API_KEY=… ADMIN_EMAIL=… ADMIN_PASSWORD=… \
npm run onboard -w @corpsol/api -- kvanta.json
```

`FIREBASE_WEB_API_KEY` — публичный ключ веб-приложения Firebase, тот же,
что `NEXT_PUBLIC_FIREBASE_API_KEY` у панели. Команда входит под
администратором и работает через API панели: те же проверки, те же
пароли «Corpsol + три цифры», те же записи в журнале.

В конце — итоги по каждому человеку и готовые сообщения с логином и
паролем для рассылки. Пароль показывается один раз: в открытом виде
система его не хранит.

## Повторный запуск

Безопасен. Отдел и сотрудники находятся по названию и логину, привязки —
по номеру, поэтому второй раз ничего не создаётся. Так можно дописать в
файл новых людей и запустить его снова.

Чего команда не делает молча — отмечает в итогах, чтобы решил человек:

- сотрудник уже заведён в другом отделе — не переносится;
- рабочий номер уже привязан к другому — не перехватывается, иначе
  звонки уйдут не тому.
